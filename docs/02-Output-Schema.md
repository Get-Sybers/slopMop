# Output schema

What `report` prints, the files it saves, and the classes those files hold.

### Layout

- Line 1 names the verb and the folder. Line 2 is the verdict: the highest severity among the
  impacts and the count at each, or `[ok] NOTHING FOUND in <n> files`. The verdict is repeated at
  the end when more than one section prints, where a terminal leaves the reader.
- A mark gives a severity or a priority: `[x]` high, `[!]` medium, `[i]` low. The marks are ASCII.
- A section is its title, then its entries indented two spaces. A section with no entry prints
  `none`.
- An entry is one line of cells, aligned with the entries around it. A column is padded to at
  most 60 characters; a longer cell runs past it.
- Detail lines stand indented under an entry, each with a label. Lines that share a label stand
  under it, and the label is written once.
- A block is an entry set apart from the next by an empty line: its name, then what it holds as
  the rows of a table, then its detail lines. A row names three things, one beside another,
  each by its identifier and its name, and a place that names nothing is empty. Each identifier
  and each name begins at the same place in every block of the section.
- Times are UTC.
- Colour is used only when standard output is a terminal, `NO_COLOR` is unset and `TERM` is not
  `dumb`; on Windows, only inside Windows Terminal. A file or a pipe receives no colour code.

### Sections

| Section | Entry | Detail lines |
| --- | --- | --- |
| Summary | a count and its breakdown; with a window of time, the row `left out`: the files outside it and what the window left out | none |
| Tactics | tactic, its ATT&CK and ATLAS identifiers, the files that show it | `intents`: the intents of those files, every one, in the order of the timeline |
| Timeline | a block for each intent, or for each period where no file names an intent: the intent or the tactics of the period, and when it ran | a row for each ATT&CK technique of its files, which an activity or a command shows: the technique, the tactic it is of and the ATLAS technique it infers, each by its identifier and its name; a row for the tools of a tactic that no technique is named for; that no technique was identified, where none was; `watchlist`: the matches of its files |
| Findings | activity, lines, tactics, techniques | `what`: the lines that show it, each with its place |
| Targeted, a group per kind | the value, for an address whether it is private or public, whether it is prior or discovered, the places in the scripts | `from`: the output that held a discovered value first; `what`: the script lines that name it |
| Targeted, a group per thing the activities acted on | the thing, such as a task, an archive or a file, and the activities that acted on it; a task also with what it runs; a resource after the activities that acted on it | `what`: the lines that act on it |
| Exposure, a group per kind, then one per service that has a group of its own | the value; where the evidence says so, what the value is, whose it is and what it is for; whether it was collected or used; the places. A password or another secret is listed by what it is first: what, collected or used, the value, the places | none |
| Impact | the impact | its statement; `exposed`: the exposed accounts and credentials it concerns; `basis` |
| Remediation | the action | its text; `exposed`; `basis` |
| Mitigation | the mitigation, the techniques found that it addresses | the framework's own sentence; `exposed`; `for`: the activities it answers |

The values are those of the classes of section 7: a block of the timeline is an `intent` row, or
is drawn from the `trace` rows of the files of its period; an entry of the tactics and of the
findings is a `finding` row; a targeted value is a `targeted` row; an exposure entry is an
`exposure` row; and the other sections are `report` rows. An activity's `lines` is its count in
the summary of the `report` class. An indicator is a `finding` row and is in no section: the
summary counts the indicators by type.

### Timeline

The timeline tells what was done, in the order of time, as a line of blocks. Where the files
name ARTEX intents, a block is an intent; where none does, a block is a period.

```text
Timeline   (a block for each intent, from the first of its files to be created until the last, or for each period of files that show the same tactics; a row is an ATT&CK technique, then its tactic and its ATLAS technique, or the tools of a tactic that no technique is named for)
  [x] i1041  2026-10-22T09:00:00Z to 2026-10-22T09:00:40Z
      T1083      File and Directory Discovery                                    TA0007  Discovery
      T1007      System Service Discovery                                        TA0007  Discovery
      T1552.005  Unsecured Credentials: Cloud Instance Metadata API              TA0006  CredentialAccess       AML.T0055  Unsecured Credentials

  [x] i1042  2026-10-22T09:05:00Z to 2026-10-22T09:05:40Z
      tools      kubectl                                                         TA0007  Discovery
      T1003.008  OS Credential Dumping: /etc/passwd and /etc/shadow              TA0006  CredentialAccess       AML.T0090  OS Credential Dumping
```

- A block names the intent, or the tactics of the period, and when it ran: one time when that is
  one instant and `-` when none of its files has a time.
- A technique is what is identified, and it is a row: the ATT&CK technique an activity or a
  command of the files shows, by its identifier and the name ATT&CK gives it, a sub-technique
  after the technique it is part of. What follows from the technique stands beside it.
- The tactic of a technique is the tactic of the activity or the command that shows it, of
  those ATT&CK files the technique under, by its ATT&CK identifier and its name. A technique
  of two such tactics has a line for each, as a scheduled task has for Execution and for
  Persistence.
- The ATLAS technique of a technique is the one whose ATT&CK reference in ATLAS is that
  technique or the technique it is a part of, or the one `analogues.json` gives it. A technique
  with two has a line for each, and one with none leaves the place empty.
- A command is a technique too, where `tactics.json` files it under one: its row is that
  technique and the tactic that holds it. A command whose technique is not named is a tool:
  the tools of a tactic are a row of their own, `tools` and the first 6 of them where a
  technique would stand, whether or not a technique gives the tactic as well.
- A tactic that neither a technique nor a tool of the block gives stands in a row alone.
- The rows stand in the order of `tactics.json`, a technique at the first of its tactics.
- A block whose files show no technique says `no MITRE ATT&CK technique identified` under its
  rows.
- The rows of the blocks are one table: the identifiers and the names of the techniques, of the
  tactics and of the ATLAS techniques each begin at the same place in every block.
- The Tactics section and the blocks say the same of an intent, each from its side. A tactic
  lists every file that shows it, a script or what a script wrote, and names the intents of
  those files; the block of each of those intents has the tactic in a row, and the block of no
  other intent does.
- A watchlist match of its files stands last, under `watchlist`.

Blocks of intents:

- Every intent has its block, in the order the intents began: the section is not cut, however
  many intents there are.
- A file is an intent's own when its name holds the name of the intent, `i` and a number, or it
  lies in the folder of the intent, as the `intent` class of section 7 sets out.
- An intent runs from the first of its files to be made until the last. A file was made at its
  creation time. A file whose creation time is after its last change is a copy, made when it was
  copied: it has the time the timeline gives it, as has a file whose file system records no
  creation time. The last line of the section counts those files.
- The saved `intents.csv` is the table of the intents: a row for each, with its period, its
  techniques and every one of its files.

Blocks of periods:

- A file is in a period when it shows a tactic, of a tool that ran in it or of an activity, or a
  watchlist match. A file that shows neither is in none, whatever its role, and ends none. The
  last line of the section counts those files.
- A period begins with a file that shows a tactic the first file of the period before did not,
  and holds the files after it for as long as each shows no other tactic. A run that turns from
  discovery to credential access begins a period there, and a file of discovery alone inside it
  does not end it.
- The tactics are those of the first file, in the order of `tactics.json`. The period runs from
  the time of its first file to the time of its last.

The saved `trace.json` holds every file with what it shows; the timeline leaves none of that out
of it.

### Places, targets and what is exposed

- A place in the evidence is written `file:line`, the line counted from 1 in the file as it
  stands. The line is left out where there is none: in a JSON, XML or HTML output, which is read
  by its values, and in a payload that was decoded out of a file.
- A line of evidence is the command as the file holds it, cut to 200 bytes, with its place. A
  finding quotes the lines that show it; so does a target.
- A target is what a line acts on, with its kind: `account svc`, `unit sync.service`,
  `file /etc/sudoers.d/svc`, `url http://203.0.113.40/s.sh`. A variable the script sets is given
  its value and keeps its name: `file /tmp/tool ($F)`. A variable the script never sets is no
  target. The targets of each kind are a group of the Targeted section, each target and then
  the activities that acted on it. A task is listed with what it runs: the command of its own
  line, or the action set on the line before it. A resource is listed after its activities, so
  the paths an activity read stand together under its name.
- An impact, an action and a mitigation list the exposed accounts and credentials they concern,
  each on a line under `exposed`, as what it is, whose it is, what it is for and its value:
  `password of admin, dc01.corp.local: Passw0rd!23`, `username: svc`. They quote no command and
  name no script: the findings do.
- What an entry concerns is every credential and every account of the kinds the entry is about,
  the credentials held in the files that show the entry, and the accounts named on the lines
  that show it. A credential is a secret, an API key or an SSH key; an account is a username or
  an email address. An account that a listed credential is of is not listed a second time.

### Limits

A long list is cut on the screen and in the saved report alike; the cut entry names the JSON file
that holds every line it omits, because the screen and the saved report share one limit.

| List | Shown |
| --- | --- |
| the files of an entry | the first 3: `a.sh, b.sh, c.sh and 4 more` |
| the periods of the timeline, where it is of periods | the first 20 and the last 20, with the number left out between them |
| each kind of target and of exposure | the first 40 |
| the lines of evidence of a finding or a target | the first 3 |
| the exposed accounts and credentials of an impact, an action or a mitigation | the first 40 of each kind |
| what one credential is used against | the first 4 |

## 2. Evidence text

Text taken from the evidence is attacker-controlled. In the report, a text prints unchanged only
when it is valid UTF-8, free of leading and trailing spaces, does not start with a double quote
and holds only printable characters. Any other text prints as a Go quoted string, so a control
sequence cannot reach the terminal and one entry line is always one line:

```text
  1  2026-10-22T09:00:00Z  script  "odd\x1b[31mname.sh"
```

A cell, a detail or a title is escaped whole. Error messages on standard error are escaped the
same way. JSON is encoded by `encoding/json`, and every rune that is not printable is then written
as a `\u` escape, so the value read back is the value in the evidence. A cell of CSV is escaped as
a cell of the report is.

## 3. Secrets

A password, a hash, a token and a key are secrets. A secret is written as it stands in the
evidence: in the exposure, inside a command quoted as evidence, in a target and as the value of
an indicator, on the screen and in every saved file. No option hides one, so the output folder
holds what the evidence holds and is to be kept as the evidence is. Only an encoded secret is
written otherwise, and only in the report, where it is decoded.

- The header of a private key block is written as the name of the key, such as `private key`:
  the key itself is in the lines below it and is not copied.
- A secret that is encoded is written decoded in the report, so that it can be read, and as it
  stands in `exposure.csv`, beside what it decodes to:
  - a JSON web token as its claims, those that say whose it is and what it is for first:
    `upn=adm@contoso.onmicrosoft.com; aud=https://graph.microsoft.com; scp=User.Read; exp=2026-11-01T10:00:00Z`;
  - base64 that holds text as that text, and base64 that holds a JSON document, such as the key
    of a service account, as its members: `type=service_account; project_id=acme-prod-4711`;
  - a key or certificate block as its type and the SHA-256 of what it holds:
    `PRIVATE KEY (PEM) SHA256:DH9xxBAhvCqRoJcb6/7pNDe+Z6hjjXppvW2mm9C8/Cs`.
- A value that is not text when it is decoded, such as an opaque token or a key in the letters
  of base64, is written as it stands. A decoded value is cut to 240 bytes and one member of it
  to 64.

## 4. The saved files

Every run saves ten files to its output folder.

| File | Holds |
| --- | --- |
| `report.txt` | the report as plain text, as the screen shows it without colour |
| `report.md` | the report as Markdown |
| `report.html` | the report as one HTML page |
| `files.csv` | the `file` class |
| `trace.json` | the `trace` class |
| `intents.csv` | the `intent` class |
| `findings.json` | the `finding` class |
| `targeted.json` | the `targeted` class |
| `exposure.csv` | the `exposure` class |
| `report.json` | the `report` class |

The three report files hold the same report: every section, whichever were named, with the same
entries and the same limits, and without the line that names the output folder.

### Markdown

- The title is the first heading, a section is a second-level heading and a group a third.
- A group whose entries have no detail lines is a table with a header row. Any other group is a
  list, each entry one item with its detail lines as items under it; a block is such an item.
- A row of a block of the timeline is an item: the technique, then its tactics and its ATLAS
  techniques, each an identifier and a name in one code span.
- Every value and every line of evidence is a code span, so a viewer shows it as written and
  makes no link, no formatting and no HTML of it.

### HTML

- `report.html` is one file that needs no other: its style is inside it, and it follows the
  light or dark setting of the browser.
- It holds no script, no image, no form and no link out of the page. The links at the top lead
  to its sections.
- Its content security policy is `default-src 'none'; style-src 'unsafe-inline'`, so a browser
  loads nothing when it is opened.
- A group is a table with a header row, and the detail lines of an entry stand in a panel under
  its row. Every text of the evidence is escaped.
- The blocks of a timeline stand one under another on a line, each with a mark on the line in
  the colour of its severity.
- The rows of the blocks are one table, headed once above the first block: the ATT&CK
  technique, the tactic and the ATLAS technique each begin at the same place in every block,
  and a rule parts one technique of a block from the next.
- On a screen no wider than 1040 pixels a technique stands on a line of its own, with its
  tactic and its ATLAS technique beside one another under it; on one no wider than 640 pixels
  each of the two has a line.

## 5. JSON

A JSON file is one array of objects, one object per row, with the keys of its class in the order
of the tables below.

```text
$ cat slopmop-ai_workdir/findings.json
[
  {
    "finding": "CertificateExport",
    "severity": "high",
    "tactic": "CredentialAccess",
    "indicator": null,
    "files": "20250302_092200_step05_export.ps1",
    "attribution": null,
    "first": "2025-03-02T09:22:00Z",
    "last": "2025-03-02T09:22:00Z",
    "attack": "T1649",
    "atlas": null,
    "evidence": [
      {
        "time": "2025-03-02T09:22:00Z",
        "file": "20250302_092200_step05_export.ps1",
        "line": 5,
        "text": "Export-Certificate -Cert $Store -FilePath ca01_20250302_092210.cer | Out-Null"
      }
    ]
  }
]
```

- Times are ISO 8601 in UTC to seconds: `2026-10-04T09:14:02Z`.
- A size is a count of bytes and a hash is whole.
- A value that does not apply is `null`.
- A list is one string, joined with `, `. Two lists are joined otherwise, because their items
  hold commas: `targets` with `; `, and the `evidence` of the `targeted` and `report` classes with
  a line break.
- The `evidence` of the `finding` class is an array of objects, one per line of evidence.

## 6. CSV

A CSV file is one line of the keys of its class, in the order of the tables below, and one line
per row.

```text
$ cat slopmop-ai_workdir/files.csv
name,path,role,size,lines,modified,created,sha256,name_time,note
20250302_090000_step01_inventory.ps1,/cases/case42/ai_workdir/20250302_090000_step01_inventory.ps1,script,487,13,2025-03-02T09:00:03Z,2026-11-18T01:20:35Z,2232e80ab6e9391a221315e0b9aaf9dd70739833a376a0e3ee4e671251be09d6,20250302_090000,
20250302_090500_step02_sync.ps1,/cases/case42/ai_workdir/20250302_090500_step02_sync.ps1,script,385,7,2025-03-02T09:05:03Z,2026-11-18T01:20:35Z,0b6610dfe1ddb50ae17a395528d915bcf73ecd032e1d849117b421c7c7af2d77,20250302_090500,
```

- The text is UTF-8 without a byte order mark, and a line ends with a line feed.
- A cell that holds a comma or a double quote stands in double quotes, with each double quote in
  it doubled.
- Times, sizes and hashes are written as in JSON. A value that does not apply is an empty cell.
- A list is one cell, joined with `, `.
- A text that begins with `=`, `+`, `-` or `@` follows an apostrophe. A spreadsheet reads such a
  cell as a formula, and the text is the attacker's.

## 7. Classes

The columns of each class are declared in `internal/command/commands.json`.

### file

One row per file, sorted by name in byte order.

| Column | Value |
| --- | --- |
| `name` | the path below the input folder, with `/` between its parts |
| `path` | the whole path of the file on the machine of the run, as its system writes it |
| `role` | `script`, `output` or `other` |
| `size` | bytes read |
| `lines` | lines of text; empty when the file has a note |
| `modified` | the modified time |
| `created` | the creation time; empty where the file system records none |
| `sha256` | SHA-256 of the raw bytes; empty when the file is unreadable |
| `name_time` | the timestamp exactly as it stands in the file name; empty when there is none |
| `note` | `binary`, `oversize`, `unreadable`, or empty |

### trace

One row per file, in time order: the time in the file name, or else the modified time.

| JSON key | Value |
| --- | --- |
| `step` | the number of the script this file belongs to; `0` before the first script |
| `name` | the path below the input folder |
| `role` | `script`, `output` or `other` |
| `time` | the file-name timestamp read as UTC, or else the modified time, as one ISO-8601 instant to the second; the file name's own token stays in the `file` class `name_time` |
| `intent` | the ARTEX intent the file belongs to, such as `i1042`; `null` when its path names none |
| `tools` | the commands the file runs or records |
| `tactics` | the tactics of those tools and of the activities |
| `transforms` | encodings and ciphers applied |
| `activities` | the activities the file shows, in the order of `activities.json` |
| `outputs` | the files a script writes |
| `indicators` | the number of distinct indicators |
| `intel` | watchlist matches as `attribution: value`; `null` without `-intelfile` |
| `note` | `binary`, `oversize`, `unreadable`, or `null` |

### finding

One row per activity, per distinct indicator and per tactic.

| JSON key | Value |
| --- | --- |
| `finding` | the activity's name, the indicator's type, or `tactic` |
| `severity` | the highest severity among the tactics; `high` for a watchlist match |
| `tactic` | the tactics of the activity, or of the files that hold the indicator |
| `indicator` | the indicator's value; `null` on an activity or tactic row |
| `files` | the files that show it |
| `attribution` | the watchlist attributions of an indicator; `null` otherwise |
| `first` | the time of the earliest file that shows it; `null` when none of its files has a time |
| `last` | the time of the latest file that shows it; `null` when none of its files has a time |
| `attack` | on an activity, its MITRE ATT&CK techniques; on a tactic, its ATT&CK tactic; `null` on an indicator |
| `atlas` | on an activity, its MITRE ATLAS techniques; on a tactic, its ATLAS tactic; `null` on an indicator |
| `evidence` | on an activity, the first 24 lines that show it, in the order of the timeline; `null` otherwise |

Each line of `evidence` is an object.

| JSON key | Value |
| --- | --- |
| `time` | the time of the file that holds the line, as the `trace` class gives it; `null` when the file has none |
| `file` | the path of that file below the input folder |
| `line` | the number of the line in the file; `null` in a structured output, where a record has no line |
| `text` | the line, as it stands |

Sort: severity from `high` to `low`, then activities, indicators and tactics, each by name.

- A tactic row lists every file that shows the tactic: a script, and an output or any other
  file that shows it. The tactics of a file are those of its `trace` row.

- An `IPv4` indicator is four numbers from 0 to 255, none with a leading zero, and may end in a
  prefix length. One that begins with `0.` is none, apart from `0.0.0.0`.
- A version number is no address. Four such numbers are left out when a fifth stands before or
  after them, when they follow `version`, `ver`, `build`, a comparison such as `==` or `>=`, `^`,
  `~`, a name and a hyphen or the name of a browser and a slash, and when a suffix such as `-rc1`,
  `-beta` or `-1ubuntu2` follows them.

### targeted

One row per IP address, hostname or email address that a script names outright: a value written
in a script, or the plain value of a variable a script sets. A secret is never a row, and
neither is a username: the `exposure` class holds both.

| JSON key | Value |
| --- | --- |
| `kind` | `email`, `device` for a hostname, or `ip` |
| `value` | the value as the script holds it |
| `origin` | `prior` when no earlier file of the timeline that is not a script holds the value: the scripts were written knowing it. `discovered` when one does: the run learnt it first |
| `from` | the place in the output that held a discovered value first; `null` on a prior one |
| `scope` | on an address, `private` for a private, loopback or link-local address and `public` for any other; a range is judged by its first address; `null` on the other kinds |
| `count` | the script lines that name the value |
| `scripts` | the first five places that name it |
| `evidence` | the script lines at those places, each with its place |

Sort: email addresses, hostnames, then addresses; `prior` before `discovered`; then by value. Two
values that differ only in case are one row.

- The email addresses and addresses are found as for the `exposure` class. A hostname is a
  device of that class or a domain name: a domain a script names is a host it reaches for.
- A host of a vendor that any script reaches for is no row: `www.google.com`,
  `graph.microsoft.com`, `login.microsoftonline.com`, a package registry, the mirror of a
  distribution, a certificate authority. `exposures.json` lists them under `vendors`; an entry
  that begins with a dot stands for every host that ends in it. A host that a tenant or a
  customer names under a vendor's domain is a row: `contoso.sharepoint.com`, a vault, a bucket.
- A `prior` value is `medium` in the report and a `discovered` one is `low`.
- A value the scripts read from an output at run time is in no script, so it is not a row.

### exposure

One row per distinct value. A secret that the evidence gives two accounts is one row for each;
one secret of one account is one row, which names everything the secret is used against.

| Column | Value |
| --- | --- |
| `kind` | `password`, `username`, `email`, `tenant`, `sshkey`, `apikey`, `application`, `resource`, `device` or `ip` |
| `value` | the value, as it stands in the evidence |
| `decoded` | what an encoded secret says once it is decoded, as section 3 sets out; empty for a value that is not encoded |
| `account` | whose a secret or an SSH key is, when the evidence says: an account or, of the secret of a client, its application; empty otherwise |
| `form` | what the value is: of a secret `password`, `hash`, `token`, `key` or `secret`; of an SSH key `public key`, `private key` or `key file`; of a resource `project`, `bucket` or `site`; empty on the other kinds |
| `service` | what the value gives access to, when the evidence says: the service a key, a token, a tenant, an application or a resource is of, such as `Microsoft 365`, `Google Cloud`, `AWS` or `GitHub`, the host of an SSH key, and each host a secret is used against, with `, ` between them; empty otherwise |
| `seen` | `collected` when the value is first seen in an output, in the order of the timeline: the scripts gathered it. `used` when it is first seen in a script: the attacker brought it |
| `severity` | `high` for a secret, an API key and an SSH key, `medium` for a username, an email address, a tenant and an application, `low` for a resource, a device and an address |
| `count` | the lines that hold the value |
| `files` | the first five places that hold it |

Sort: the kinds in the order above, `collected` before `used`, then by value.

- A username is a value under a field that names an account; the account a command signs in
  as, runs as, makes, changes or puts in a group; the account of a `passwd` line, of a rule of
  `sudo`, of a session or of the output of `id` and `whoami`; a home or profile folder; a
  remote login; a `DOMAIN\user`; and whose a credential is said to be. A domain before the
  name is dropped.
- A word is no username because it follows a field name: a value that stands bare, after a
  space, and is followed by the rest of a sentence is left out, as `verify` is in
  `Check user: verify the account exists`. Neither is a number, a date, a version, an
  identifier, a hash, a file name, a placeholder such as `username`, or the system itself.
  The same holds for a device and a tenant, and for a secret that is one plain word.
- An email address and an IP address are the indicators of those types. A loopback address is
  left out.
- A device is a value under a field that names a host, the host of a share, a scan report or a
  remote login, a name a tool reports, and a name in `.local`, `.lan`, `.internal`, `.corp` or
  `.intranet`.
- A secret is a value under a field whose name ends as `password`, `secret` or `token` does, a
  password a tool reports or is given, the hash of a dumped account or of a `shadow` line, a
  password inside an address, the name and password of basic authentication, a bearer token,
  and the indicators `JWT` and `PrivateKey`. The same NT hash is one value however it is
  written. A value that holds no letter and no digit, such as a rule of `=` signs, is none.
- An API key is a value under a field whose name ends as `apikey`, `secretkey` or `accesskey`
  does, the indicator `AWSKey`, and a value in the form a service gives its keys, such as
  `ghp_`, `sk-`, `xoxb-` or `AIza` and what follows. A token that is
  the key of a service is listed as that key and not as a secret too.
- A tenant is a directory identifier or a domain under a field that names a tenant, after
  `-TenantId` or `--tenant`, in the address of a Microsoft login, and a domain of
  `onmicrosoft.com`.
- An SSH key is a public key, named by its fingerprint as `ssh-keygen -l` gives it, with the
  user and the host of its comment or the host of its line in `known_hosts`; the header of a
  private key of SSH; and the key file `ssh`, `scp` or `sftp` is given with `-i`, with the user
  and the host it opens.
- An application is the identifier of a client under a field that names one or after
  `-ClientId`: a directory identifier, or a client of Google. A resource is a project of Google
  Cloud, a bucket of Google Cloud or of AWS, and a site of SharePoint.
- The service of a value is the one its own form shows, such as the key of a provider, a
  directory identifier of a tenant or an address of `gserviceaccount.com`; else the one that
  issued a JSON web token, by the host its claims name; else the one a word of its field name
  names, as `AZURE_CLIENT_SECRET` and `OPENAI_API_KEY` do.
- What is of Microsoft 365 and what is of Google Cloud is listed in the report a second time, in
  a group of that service, whatever its kind: a tenant, an application, a secret, a token, an
  account, a project. The saved file holds each value once, with its `service`.
- A value is folded into the same value of which the evidence says more: whose it is, or what
  it is for. A secret of one account is one row under either way of writing the account,
  `svc` and `svc@corp.example`. An account that is a username and an email address is listed
  as the address.
- A secret takes the account of its own record or tool option. One that neither gives an
  account is of the one account its line names, or of the one application where the line names
  no account; a line that names two is not read so. Under a field name it takes the username
  read at most three lines before it, unless both field names begin differently: `DB_PASSWORD`
  is the password of `DB_USER` and `API_TOKEN` is not. A JSON web token is of the account its
  claims name: `upn`, `preferred_username`, `email`, or else the application or the subject.
- A secret is for the service that is known of it; else for what a token says it is for, its
  audience; else for the one host its line names: the device a rule finds on the line, or else
  the host of an address, of a share or of a remote desktop, or an IP address. A host of a
  service that is known is written as the service. A secret of an account or an application of
  a service is for that service.
- A value that is a variable is given what the script sets it to; a placeholder is left out.

### report

One row per line of the report, in six sections.

| Section | A row is |
| --- | --- |
| `summary` | a count: `files`, `scripts`, `outputs`, `left out` with `-start` or `-stop`, `indicators` and one per type, `activities` and one per activity, `tactics`, `targeted` and one per kind, `exposed` and one per kind, `intents` when a file belongs to one, and `intel hits` with `-intelfile` |
| `targeted` | a value a script names outright, as the `targeted` class holds it: `item` is the value, `value` is `medium` for a prior one and `low` for a discovered one, `detail` the kind, the origin, the scope and the place that held it first, `files` the places in the scripts and `evidence` the lines |
| `exposure` | an exposed value, as the `exposure` class holds it: `item` is the value, `value` the severity, `detail` the kind, whose a secret is and whether it was collected or used, and `files` its places |
| `impact` | a consequence the evidence shows |
| `remediation` | an action that undoes what was done |
| `mitigation` | a mitigation that MITRE ATT&CK or MITRE ATLAS gives for a technique that was found |

| JSON key | Value |
| --- | --- |
| `item` | the name of the count, the value, the impact or the action; on a mitigation, its identifier and name, such as `M1038 Execution Prevention` |
| `section` | the section |
| `value` | a number on a summary row, where an `activities <name>` row counts the lines that show the activity; elsewhere `low`, `medium` or `high`: the severity of a value or an impact, the priority of an action; a mitigation takes the highest severity among the activities it addresses |
| `detail` | on an impact, its statement and the hosts or addresses affected; on a remediation, what to do; on a mitigation, the first sentence of the framework's own description; on the summary row `left out`, what the window left out: `before 2026-10-22T09:10:00Z or after 2026-10-22T09:20:00Z`; `null` on any other summary row |
| `basis` | on an impact or an action, the activities, tool tactics and watchlist attributions that call for it; on a mitigation, the activities it answers, none where only commands show its techniques |
| `files` | on an impact or an action, the files that show it |
| `attack` | the ATT&CK techniques an impact shows, by its activities and by the commands of its tool tactics; on an ATT&CK mitigation, the techniques found that it addresses |
| `atlas` | the ATLAS techniques an impact shows; on an ATLAS mitigation, the techniques found that it addresses |
| `targets` | on an impact or an action, what its activities act on; on a mitigation, each activity it answers with what that activity acted on |
| `evidence` | on an impact or an action, the lines that show it, each with its place: up to 24 of each activity and of the tools of each tactic |
| `exposed` | on an impact, an action or a mitigation, every exposed account and credential it concerns, one to a line, as the report writes them; `null` when it concerns none |

Sort: the sections in the order above; impacts from `high` to `low`;
remediation from `high` to `low`; then the ATT&CK mitigations and the ATLAS mitigations, each from
`high` to `low` and by identifier.

An impact says what the evidence shows was done. The tool does not run a script, so it cannot say
whether a step succeeded.

### intent

One row per ARTEX intent, in the order the intents began. ARTEX gives each intent a run folder,
`tasks/<task>/i<number>`, and names the session of its worker `exp<number>-worker-i<number>`. A
file belongs to the intent its own name holds, or else to the one whose folder it lies in, at any
depth, or whose session its path names.

| Column | Value |
| --- | --- |
| `from` | when the first of its files was made; empty when no file has a time |
| `until` | when the last of its files was made |
| `intent` | the identifier, `i` and the number, such as `i1042` |
| `attack` | the ATT&CK techniques of the activities its files show and of the commands they run |
| `atlas` | the ATLAS techniques those techniques infer |
| `files` | its files, every one, in time order |
| `task` | the task of the run folder; empty when the path does not give one |
| `seconds` | the seconds from `from` to `until`; `0` for a single file |
| `timed_by` | `creation` when every file is timed by its creation time, `name or modified` when none is, `both` otherwise; empty when no file has a time |
| `severity` | the highest severity among the tactics of its files; empty when they show none |
| `tactics` | the tactics of its files |
| `activities` | the activities its files show |

- A file name holds the name of an intent when `i` and a number stand in it with no letter and no
  digit before or after them: `i1042_scan.sh`, `cmd-i1042.stdout.txt` and `i1042` do, and
  `wifi7.txt` and `i18n.json` do not. The first such name in a file name decides, and the name
  of a file decides before the folder it lies in.
- A file is made at its creation time, the `created` of the `file` class. A creation time that is
  after the last change is that of a copy: such a file, and one with no creation time, has the
  time of the `trace` class, the timestamp in its name or else its modified time. Evidence that is
  read where it was written, or copied with its creation times kept, is timed by `creation`.
- The name `i386`, `i486`, `i586` or `i686` is no intent.
- When the folder read is a run folder itself, its files belong to that intent.
- A file that neither its name nor its folders give an intent belongs to none and is in no row.
